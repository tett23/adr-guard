# ADR 0004: ADR 0003 の変更を `v0.2.1` としてリリースする

ステータス: 採択

## 文脈

ADR 0003 は、`--version` と `--help` を機能の追加とみなし、マイナーバージョンを上げて `v0.3.0` としてリリースするとした。
しかし、この変更は3つのサブコマンドの挙動を変えず、使う側のリポジトリのhookやCIの結果にも影響しない。
`v0.2.0`（ADR 0002）でADRの保護の対象が広がったこととは性質が異なり、マイナーバージョンを上げるほどの変更ではないと判断した。

## 実装すること

- ADR 0003 の変更を、`v0.3.0` ではなく `v0.2.1` としてリリースする。`Cargo.toml` の `version` を `0.2.1` にする。
- README のインストール手順の例（タグと `adr-guard --version` の出力）を `v0.2.1`・`adr-guard 0.2.1` にする。
- ADR 0003 のテスト設計の「リリース」の節は、`v0.3.0` を `v0.2.1`、`adr-guard 0.3.0` を `adr-guard 0.2.1` と読みかえて確かめる。
- 採択後、ADR 0003 のステータスを `採択→リリースのバージョンはADR 0004` に変更する。

## 実装しないこと

- ADR 0003 のバージョン以外の内容（`--version` と `--help` の仕様、リリースのワークフローでの確認）の変更。
- バージョンの上げ方の規則（どの変更でマイナーとパッチのどちらを上げるか）を定めること。

## テスト設計

- `v0.2.1` のリリースで、両方のターゲットのビルドが、リリースのワークフローのバージョンの確認（ADR 0003）を通ることを確かめる。
- ダウンロードしたバイナリで、`adr-guard --version` が `adr-guard 0.2.1` を表示すること、`adr-guard --help` がヘルプを表示することを確かめる。

## トレードオフ

- オプションの追加をパッチバージョンで出すため、バージョン番号だけを見て `--version` と `--help` があるかを判断することはできない（`v0.2.0` には無く、`v0.2.1` には有る）。使う側の挙動に影響しない追加であるため、許容する。
