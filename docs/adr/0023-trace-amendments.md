# ADR 0023: trace で元の決定から修正ADRをたどる

Status: proposed

## 文脈

[ADR 0001](0001-standalone-adr-guard.md) のステータスには、ディレクトリとステータス行の判定について別々の修正先がある。
ディレクトリについては、その先の [ADR 0002](0002-module-adr-directories.md) でも深さと名前で修正先が分かれる。
一つの番号を「最新版」として返すと、別の部分について今も効力のある決定を見落とす。

## 調査した事項

[src/status.rs](../../src/status.rs) の `Change` は変更部分と番号の列を保持する。
`changes_ja` と `changes_en` はリンクの表示文字を読んでおり、この列からリンク先のディレクトリは復元できない。
[ADR 0019](0019-module-qualified-adr-references.md) はモジュールを指定した参照を扱う。

## 実装すること

`adr-guard trace <ADRのパス>` は作業ツリーを読み、指定したADRから修正先へ向かう経路を標準出力に表示する。
入力パスは呼び出し元からの相対パスまたは絶対パスとし、表示にはリポジトリルートからの相対パスを使う。
既定は `--list` とし、端末とパイプで同じ出力を返す。
`--graph` を付けると枝線のある木を出す。両オプションの同時指定は引数エラーとする。

### 枝線で読む形式

`--graph` は一行目に起点を置き、各子の前に兄弟が続く場合は `├── `、最後なら `└── ` を付ける。
祖先の深さごとに、後続の枝がある場合は `│   `、なければ空白四つを置く。
子には変更部分、` -> `、修正先パスを表示し、部分名がない場合は `(範囲指定なし)` とする。

```text
docs/adr/0001-a.md
├── 入力 -> docs/adr/0002-b.md
│   └── 字句 -> docs/adr/0004-d.md
└── 出力 -> docs/adr/0003-c.md
```

### awk で読む形式

`--list` はヘッダーなしの TSV で、各行を「種別、元のパス、修正先のパス、部分名」の四列で出力する。
起点行の種別は `root` とし、起点を第三列に置き、第二列と第四列は空にする。
残りは修正先一件ごとに `edge` を一行出し、部分名なしは空欄にする。
合流を示す辺も同じ四列で出す。
例えば次のパイプラインは、部分名が「入力」の修正先を取り出す。

```sh
adr-guard trace --list docs/adr/0001-a.md | awk -F '\t' '$1 == "edge" && $4 == "入力" {print $3}'
```

両形式ともフィールド内のバックスラッシュ、タブ、CR、LF をそれぞれ `\\`、`\t`、`\r`、`\n` にエスケープし、各レコードを LF で終える。

## アルゴリズム

各ADRのステータスが Superseded の場合だけ、修正先を記載順に深さ優先で展開する。
[ADR 0022](0022-status-transitions.md) の新形式なら各変更の `by` のパスをそのままルートから解決する。
旧形式では次の規則で参照を解決する。

参照は一つずつ、元のステータス行にあるリンク先、修飾名、番号を対応づけたまま読む。
Markdown リンクは文書からの相対パスを解決し、表示の番号とリンク先ADRの番号が一致することを確かめる。
リンクのない修飾名は既存のモジュール参照規則で、修飾のない番号は `links` と同じ候補ディレクトリの順で解決する。
候補ディレクトリ内で同番号が重複した場合は曖昧として失敗する。
リンクの表示にモジュールの修飾名がある場合は、その修飾名と番号から解決したパスもリンク先と一致することを確かめる。
いずれも対象を作業ツリーのADR一覧に限る。

Superseded の変更列が空の場合と、一つでも修正先番号を持たない変更がある場合は、修正先の欠落とする。
同じADRが別経路から再び現れたら、グラフ形式ではその行に ` [表示済み]` を付け、両形式とも子の再展開を省く。
現在の経路上の祖先への辺は循環として先に検出する。
循環、修正先の欠落や曖昧さ、到達した文書のステータス行の欠落や重複、読み込み失敗では、標準エラーに該当パスと原因を出して終了コード1とする。
新形式の構文エラーはパスと原因を示して終了コード1とする。
旧形式の行が一つあり値が Unknown の場合は葉とする。
失敗時に途中の木を成功結果と取り違えないよう、標準出力には検証を終えた木だけを書く。
起点がADR一覧にない場合も、指定パスを標準エラーに出して終了コード1とする。
成功は0、引数の個数やオプションの誤りは64とする。

## 実装しないこと

本文中の参考文献、Git 履歴からの推測、修正先から元のADRへの逆引き、文書の書き換えは対象外とする。

## 不変条件

1. 成功時は起点を一行目に置き、到達した各ADRの修正先を記載順に一度だけ展開する。
2. 同じ番号が複数モジュールにあっても、各辺は指定した対象だけを指す。
3. 到達範囲の壊れた辺と循環を検出すると有限回で停止し、標準出力は空になる。

| 起点からの入力 | 期待結果 |
|---|---|
| 修正なし | 起点一行、成功 |
| 修正先一件 | 起点と子の二行、成功 |
| 二枝が同じ孫に合流 | 二度目は辺だけを出し、グラフ形式では表示済みの印を付けて成功 |
| 修正を示すが番号がない | 失敗 |
| 自己参照または二件の循環 | 失敗 |

## テスト設計

一時リポジトリで `inv1_trace_order` により両形式の出力例、分岐、合流、本文だけにある参照の除外をバイト単位で比較する。
`inv2_trace_target` は同番号の二モジュール、相対リンク、修飾名、裸の番号を組み合わせる。
`inv3_trace_failure` は境界表の失敗例に加え、リンク切れ、番号不一致、曖昧な番号、ステータス行の欠落と重複を調べる。
`inv1_list_fields` は起点のみ、部分名なし、引用符、タブ、改行、バックスラッシュを含む部分名で全行が四列になることと、例の awk が対象のパスだけを返すことを確かめる。
すべてのケースで終了コードと二つの出力先を別々に検査する。

## トレードオフ

パスを起点にすると番号が重なるリポジトリでも起点を特定できるが、入力は長くなる。
表示済みの印により合流先の展開を一度に抑えつつ、どの部分からそこへ到達したかを残せる。
