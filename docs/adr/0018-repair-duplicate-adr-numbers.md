# ADR 0018: 重複したADRの番号を検出し、番号を振りなおして修復できるようにする

ステータス: 採択（未実装）

## 文脈

ADRのファイル名には `0001-feature-details.md` のように連番を付ける（[ADR 0001](0001-standalone-adr-guard.md)）。
ADRは作成した時点ではコミットせずにレビューを受けるため、複数のブランチや複数のエージェントで同時にADRを書くと、同じ番号を使ってしまうことがある。
それぞれのブランチがマージされると、同じディレクトリに `0017-a.md` と `0017-b.md` のように、番号が重複したADRが並ぶ。

番号が重複すると、次の問題が起きる。

- 文書の `ADR 0017` が、どちらのADRを指すのか分からない。`links` は参照先がちょうど1つのときだけリンクを付けるため（[ADR 0009](0009-require-links-for-adr-references.md)）、どちらにもリンクを付けられない。
- `採択→…は[ADR 0017](...)` のようなステータスの行や、ADR同士の参照が読み手を迷わせる。

いまは重複を検出する手段がなく、気づいても直す手段がない。
コミット済みのADRのファイル名を変える変更は、削除と追加として拒否される。直すには緊急用のトレーラー（[ADR 0008](0008-allow-intentional-adr-rewrites.md)）が要る。

番号の振りなおしは、ADRの内容（決定とその理由）を変えない、決まった形の作業である。
そこで、重複を検出する検査と、番号を振りなおすサブコマンドを加え、その振りなおしを検査のオプションで許可する。

## 実装すること

### 重複の判定

- 同じADRのディレクトリ（[ADR 0002](0002-module-adr-directories.md)、[0011](0011-nested-adr-directories.md)、[0014](0014-directory-name-variants.md)）の直下にある、ファイル名が `<4桁の数字>-` で始まる `.md` のADRについて、同じ番号を持つものが2つ以上あれば「番号の重複」とする。
- 別のディレクトリ（`docs/adr/` と `docs/server/adr/` など）の同じ番号は重複としない。

### `adr-guard check-numbers`

- 作業ツリーのすべてのADRのディレクトリについて、番号の重複を検査する。
- 重複があれば、重複ごとに `check-numbers: <ディレクトリ>: ADR <番号> が重複しています: <ファイル名>, <ファイル名>` を標準エラーに表示し、最後に `adr-guard renumber で修復できます。` を表示して、終了コード1で終わる。無ければ何も表示せずに終了コード0で終わる。
- composite actionで、`check-status` の後に `adr-guard check-numbers` を実行する。入力 `check-numbers`（既定は `true`）を加え、`false` のときは実行しない。
- pre-commit hookでは検査しない（重複は、別々のブランチがマージされたときに生じるため）。

### `adr-guard renumber [--dry-run]`

番号の重複を、番号を振りなおして修復する。

1. 振りなおすADRを決める：重複した番号のADRのうち、gitの履歴で最初に追加された（`git log --diff-filter=A` の最も古いコミットの）ものを残し、それ以外を振りなおす。追加された時刻が同じか、まだコミットされていないADRどうしは、ファイル名の昇順で先のものを残す。
2. 新しい番号を決める：そのディレクトリのADRの最大の番号の次から、順に割り当てる。
3. ファイル名を変える：`<旧番号>-<名前>.md` を `<新番号>-<名前>.md` にする。`<名前>` の部分は変えない。
4. 振りなおしたADRのタイトルの行（1行目が `# ADR <旧番号>:` で始まるもの）の番号を、新しい番号にする。
5. 参照を直す：作業ツリーのすべての `.md` について、リンク先が振りなおしたADRのファイルを指すリンク（[ADR 0009](0009-require-links-for-adr-references.md) のインラインのリンク）のリンク先を、新しいファイル名にする。そのリンクのテキストが `ADR <旧番号>` か `<旧番号>` なら、番号を新しい番号にする。
6. 振りなおしの一覧（`<ディレクトリ>: <旧ファイル名> -> <新ファイル名>`）と、直した参照の件数を標準エラーに表示する。

- ファイル名の変更は作業ツリーで行い、`git mv` はしない。コミットは人が行う。
- `--dry-run` では、ファイルを変えずに、行う変更の一覧だけを表示する。
- 重複が無ければ、何もせずに終了コード0で終わる。
- リンクの無い参照（`ADR 0017` だけの本文）は、どちらのADRを指すか分からないため直さない。そのような参照があれば、`<パス>:<行>: ADR <旧番号> はどちらのADRを指すか分からないため、直していません` を表示する。

### `--allow-renumber`（`pre-commit` と `check-range`）

`renumber` で行った変更を含むコミットを許可する。

- 次をすべて満たす削除と追加の組を、「番号の振りなおし」とする。
  - 削除されたADRと追加されたADRが同じディレクトリにあり、ファイル名の `<名前>` の部分（番号と `-` の後ろ）が同じで、番号が違う。
  - 変更前の状態で、削除されたADRと同じ番号のADRが、同じディレクトリにほかにもあった（重複していた）。
  - 追加されたADRの内容が、削除されたADRの内容と、タイトルの行の番号を除いて同じである（`--allow-status`、`--allow-links` を付けていれば、それぞれの正規化をしてから比較する）。
- 番号の振りなおしは、コミット済みのADRの削除・移動の違反としない。
- 同じコミットのほかのADRの変更では、リンクのテキストのADRの番号のうち、振りなおした新しい番号を古い番号に読みかえてから比較する。`--allow-links` と合わせて、`[ADR <旧番号>](<旧ファイル名>)` を `[ADR <新番号>](<新ファイル名>)` に直す変更が許可される。
- `--allow-renumber` を付けない場合の挙動は変えない。actionに入力 `allow-renumber`（既定は `false`）を加える。

### `--help`、README、仕様

- `--help` に `check-numbers` と `renumber` と `--allow-renumber` を加える。
- README に「ADRの番号が重複した場合」の手順を記載する（`check-numbers` で検出し、`renumber` で直し、`--allow-renumber` を付けた検査のもとでコミットする）。
- `docs/specifications.md` に、重複の判定、`check-numbers`、`renumber`、`--allow-renumber` を記載する。
- 使い方の1行に `check-numbers`、`renumber [--dry-run]`、`--allow-renumber` を加える。

### リリース

- actionの既定で `check-numbers` を実行し、重複のあるリポジトリのCIが失敗するようになるため、マイナーバージョンを上げて `v0.9.0` としてリリースする。

## 実装しないこと

- pre-commit hookでの重複の検査。
- 番号の欠け（`0001`、`0003` のように間が空くこと）の検査。破棄したADRの番号は欠番とする運用があるため。
- どのADRを残すかを選ぶオプション。履歴で先に追加されたものを残す規則に固定する。
- リンクの無い参照の自動の修正と、本文の中の `ADR <番号>` の自動の書きかえ。
- 振りなおしたADRのステータスの行の自動の変更。
- 記録（[ADR 0013](0013-protect-audit-and-benchmark-records.md)）の中のリンクの修正。記録は変更できないため、記録の中の古いリンクはそのまま残る。

## テスト設計

### 既存のテスト

既存のテストは変えずにすべて通す。

### 単体テスト

- 重複の判定：同じディレクトリの `0017-a.md` と `0017-b.md` は重複、`docs/adr/0017-a.md` と `docs/server/adr/0017-a.md` は重複しない、`0017.md`（`-` の無いもの）は対象外。
- 新しい番号の割り当て：最大の番号の次から割り当て、重複が複数あれば順に割り当てる（`0017` が2つ、`0020` が最大なら `0021`）。
- リンクの書きかえ：`[ADR 0017](0017-b.md)` は `[ADR 0018](0018-b.md)`、`[参照](0017-b.md)` は `[参照](0018-b.md)`、残すADRへのリンク `[ADR 0017](0017-a.md)` は変えない。相対パス（`../adr/0017-b.md`、`docs/adr/0017-b.md`）も直す。
- 番号の振りなおしの判定：上の条件をすべて満たす組だけを振りなおしとみなし、`<名前>` が違う組、重複していなかった番号の組、内容がタイトルの番号以外でも違う組は振りなおしとみなさない。

### 結合テスト

`docs/adr/0017-a.md` と `docs/adr/0017-b.md` を別々のコミットで追加し、`0017-b.md` を `README.md` と `docs/adr/0016-x.md` からリンクした一時リポジトリで、次を確かめる。

- `check-numbers`：重複を表示して終了コード1。重複が無いリポジトリでは終了コード0。
- `renumber --dry-run`：ファイルを変えずに `docs/adr: 0017-b.md -> 0018-b.md` を表示する。
- `renumber`：`0017-b.md` が `0018-b.md` になり、タイトルの行が `# ADR 0018:` になり、`README.md` と `0016-x.md` のリンクが `[ADR 0018](...0018-b.md)` になる。その後の `check-numbers` と `links` が終了コード0で終わる。
- `renumber` の後の変更をステージすると、`pre-commit --allow-status --allow-links` は拒否し、`pre-commit --allow-status --allow-links --allow-renumber` は許可する。コミットした範囲を `check-range --allow-status --allow-links --allow-renumber` は許可する。
- 重複していないADRのファイル名を手で変えた変更は、`--allow-renumber` を付けても拒否する。振りなおしたADRの本文も変えた変更は、`--allow-renumber` を付けても拒否する。
- `check-numbers x`、`renumber x` は終了コード64。

### リリース

`v0.9.0` のリリース後、ダウンロードしたバイナリで、上の一時リポジトリの重複を `renumber` で直し、`check-numbers` が終了コード0で終わることを確かめる。

## トレードオフ

- 振りなおすADRを、履歴で後から追加されたほうに固定する。先に採択されたADRの番号を変えないことを優先する。後から追加されたほうがよく参照されている場合も番号が変わるが、リンクは `renumber` が直す。
- リンクの無い参照は直さない。`links` の検査（[ADR 0009](0009-require-links-for-adr-references.md)）のもとでは、参照にはリンクが付いているはずであり、残るのは例外的な場合だけである。
- `--allow-renumber` で、同じコミットのほかのADRのリンクのテキストの番号の変更も許可する。振りなおした番号だけを読みかえるため、無関係な番号の変更は許可されない。一方、残したADRへのリンクの番号を誤って新しい番号に変える変更も、比較の上では許可される。`renumber` の出力とプルリクエストのレビューで確かめる。
- 記録の中のリンクは直せないため、振りなおしたADRへの記録の中のリンクは切れる。記録は作成した時点の内容を残すものであり、リンクが当時の番号を指すことは許容する。
- `check-numbers` をactionの既定で実行するため、重複のあるリポジトリは v0.9.0 に上げるとCIが失敗する。`check-numbers: false` で止められる。
