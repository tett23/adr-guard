# ADR 0008: 意図してADRを書きかえるコミットを、コミットメッセージのトレーラーで許可する

ステータス: 採択

## 文脈

adr-guard は、コミット済みのADRのステータスの行以外の変更を、pre-commit hook、Claude Codeのhook、CIの `check-range` の3か所で拒否する（[ADR 0001](0001-standalone-adr-guard.md)）。

しかし、ADRの内容を変えずに書式だけを直したい場合など、人間が判断したうえでADRを書きかえたいことがある。
実際に、ADRの本文の「ADR NNNN」をリンクに置きかえたコミット（`80593fe`）では、手元はpre-commit hookを `--no-verify` で迂回できたが、CIの `check-range` を通す手段がなかった。
そのため、プルリクエストと `main` へのpushのCIで `adr` ジョブが失敗し、失敗を許容してマージした。

CIの失敗を許容する運用を続けると、意図しない書きかえによる失敗と見分けがつかなくなる。
書きかえが意図したものであることと、その理由をコミットに記録し、そのコミットだけを検査で許可できるようにする。

## 実装すること

### トレーラー `ADR-Guard-Allow`

- コミットメッセージのトレーラーに `ADR-Guard-Allow: <理由>` があるコミットを、「ADRの書きかえを許可したコミット」とする。
  - トレーラーは、gitのトレーラーの規則（コミットメッセージの最後の段落）に従う。gitの `%(trailers:key=ADR-Guard-Allow,valueonly)` で取り出す。キーの大文字と小文字は区別しない（gitの挙動のまま）。
  - 理由（値の前後の空白を除いたもの）が空の場合は、許可しない。
  - 例：

    ```
    Link ADR references in documents

    ADR-Guard-Allow: ADRの内容を変えずに、参照をリンクにするため
    ```

### `adr-guard check-range`

- 許可したコミットでは、ADRの変更・削除・リネームを違反としない。
  - 違反になるはずの変更があった場合は、コミットごとに `check-range: <コミット>: ADR-Guard-Allow により許可しました: <理由>` を標準エラーに表示する。
- 許可は、トレーラーを付けたコミットだけに及ぶ。同じ範囲のほかのコミットは従来どおり検査する。
- マージコミットを検査しないこと（[ADR 0001](0001-standalone-adr-guard.md)）は変えない。

### `adr-guard pre-commit`

- pre-commit hookの時点ではコミットメッセージがまだ無いため、トレーラーは使えない。代わりに環境変数 `ADR_GUARD_ALLOW` を使う。
  - `ADR_GUARD_ALLOW` の値（前後の空白を除いたもの）が空でなければ、違反があっても成功する。そのとき、`pre-commit: ADR_GUARD_ALLOW により許可しました: <値>` を標準エラーに表示する。
  - 例：`ADR_GUARD_ALLOW=リンクにするため git commit`
  - `--no-verify` と違い、同じpre-commit hookに並べたほかの検査は迂回しない。
- `ADR_GUARD_ALLOW` はコミットメッセージには記録されない。CIを通すには、別にトレーラーを付ける必要がある。

### ドキュメントとリリース

- `docs/specifications.md` に、トレーラーと環境変数による許可を記載する。
- `README.md` に「意図してADRを書きかえる場合」の手順（`ADR_GUARD_ALLOW` でコミットし、コミットメッセージに `ADR-Guard-Allow` のトレーラーを付ける）を記載する。
- CIの検査の結果が変わる変更のため、[ADR 0004](0004-release-version-options-as-patch.md) の判断（hookやCIの結果に影響しない変更はパッチバージョン）に従わず、マイナーバージョンを上げて `v0.3.0` としてリリースする。

## 実装しないこと

- Claude Codeのhook（`claude-hook`）での許可。Claude Codeに意図してADRを書きかえさせる場合は、人間がhookを外すか、シェルから書きかえる。
- 許可するファイルをトレーラーで限定すること（`ADR-Guard-Allow: docs/adr/0001-x.md` など）。トレーラーを付けたコミットでは、すべてのADRの変更を許可する。
- 許可したコミットの一覧を出力するサブコマンド。`git log --format='%h %(trailers:key=ADR-Guard-Allow,valueonly)'` などで確かめる。
- プルリクエストのラベルなど、GitHub固有の仕組みによる許可。
- 過去のコミット（`80593fe`）への遡った適用。`check-range` の範囲から外れているため、今後のCIには影響しない。

## テスト設計

### 結合テスト

既存のテストは変えずにすべて通す。そのうえで次を追加する。

`check-range`：

- 本文を変えたコミットに `ADR-Guard-Allow: 理由` を付けると成功し、標準エラーに理由が含まれる。
- 削除とリネームのコミットにトレーラーを付けると成功する。
- キーを小文字（`adr-guard-allow: 理由`）にしても成功する。
- 値が空（`ADR-Guard-Allow:` だけ、または空白だけ）なら失敗する。
- 最後の段落ではない位置（本文の途中）に書いた `ADR-Guard-Allow: 理由` では失敗する。
- 似た別のキー（`ADR-Guard-Allowed: 理由`）では失敗する。
- トレーラーを付けたコミットと、付けずに本文を変えたコミットが同じ範囲にあれば失敗し、付けなかったコミットだけが違反として報告される。
- トレーラーを付けても違反が無いコミットでは、許可のメッセージを表示しない。

`pre-commit`：

- `ADR_GUARD_ALLOW=理由` で、本文を変えた変更が成功し、標準エラーに理由が含まれる。
- `ADR_GUARD_ALLOW` が空、または空白だけなら、従来どおり失敗する。

### リリース

`v0.3.0` のリリース後、ダウンロードしたバイナリで、トレーラーを付けてADRを書きかえたコミットを含む一時リポジトリに対して `check-range` が成功することと、トレーラーを外すと失敗することを確かめる。

## トレードオフ

- トレーラーを付ければ、誰でもADRの書きかえを通せる。書きかえを完全に防ぐのではなく、意図しない書きかえを防ぎ、意図した書きかえを理由とともに履歴に残すことを優先する。トレーラーはプルリクエストのレビューで目に入るため、レビューで確かめる。
- 許可がコミットの単位のため、書きかえを許可したいADRと、許可したくないADRの変更を同じコミットに入れると、両方が許可される。意図した書きかえは、ほかの変更と分けて1つのコミットにする運用で補う。
- pre-commit（環境変数）とCI（トレーラー）で手段が分かれるため、片方だけを付け忘れることがある。READMEの手順で両方を示す。
- プルリクエストをスカッシュでマージすると、トレーラーがマージ後のコミットメッセージに残るかはマージの設定による。このリポジトリでは常にマージコミットでマージするため、元のコミットがそのまま残る。
