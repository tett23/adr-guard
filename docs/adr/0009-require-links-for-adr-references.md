# ADR 0009: リンクの無いADRの参照をエラーにし、自動で修正する

ステータス: 採択

## 文脈

ADRや仕様、READMEでは、ほかのADRを `ADR 0001` のように番号で参照する。
このリポジトリと send-to-kindle では、これらの参照をADRのファイルへのリンク（`[ADR 0001](0001-standalone-adr-guard.md)`）に置きかえた。
しかし、新しく書く文書でリンクを付け忘れても、検出する手段がない。

付け忘れたままコミットしたADRは、本文を書きかえられない。
あとからリンクを付けるには、[ADR 0008](0008-allow-intentional-adr-rewrites.md) のトレーラーで書きかえを許可するしかない。
しかしトレーラーは、どんな書きかえでも通す緊急用の手段であり、リンクを付けるという決まった作業に日常的に使うものではない。

そこで、リンクの無いADRの参照をコミットの時点とCIでエラーにし、リンクを自動で付けるサブコマンドを加える。
コミット済みのADRにリンクを付ける変更は、トレーラーではなく、検査のオプションで許可する。

あわせて、AI（Claude Codeなど）がヘルプだけを読んで adr-guard を正しく使えるよう、`--help` を詳しくする。

## 実装すること

### ADRの参照

- `ADR` に半角の空白1つと4桁の数字が続く文字列（`ADR 0001`）を、ADRの参照とする。前後が英数字に続く場合（`XADR 0001`、`ADR 00012`）は参照としない。
  - `ADR 0005、0006` や `ADR 0005, 0006` のように、`、` または `,`（後ろに空白があってもよい）で区切って4桁の数字が続く場合は、続く数字もそれぞれ参照とする。
- 次の箇所にある参照は対象外とする。
  - フェンスで囲んだコードブロック（` ``` ` または `~~~` で始まる行から、同じ記号で始まる行まで）の中
  - インラインのコード（同じ数の `` ` `` の並びで囲んだ部分。`` `` `ADR 0001` `` `` のように2つ以上で囲んだものも含む）の中
  - リンクのテキストの中（`[ADR 0001](...)`、`[...ADR 0001...](...)`、参照形式のリンク `[ADR 0001][1]`）
  - ADRのファイルの中で、そのADR自身の番号を指す参照（タイトルの `# ADR 0001: ...` など）

### 参照先の解決

- 文書のパスから、参照先のADRのディレクトリを次の順に決める。
  - 文書が `docs/<モジュール>/` 以下（`<モジュール>` は `adr` 以外）にあり、`docs/<モジュール>/adr/` に参照の番号のADRがあれば、そのディレクトリ（[ADR 0002](0002-module-adr-directories.md)）
  - そうでなければ `docs/adr/`
- ディレクトリの中で、ファイル名が `<番号>-` で始まり `.md` で終わるファイルがちょうど1つあれば、それを参照先とする。
- 参照先が見つからない参照（ほかのリポジトリのADRなど）は、エラーにも修正の対象にもしない。

### 対象の文書

- 作業ツリーにある `.md` のファイルのうち、`git ls-files --cached --others --exclude-standard` で列挙されるもの（[ADR 0005](0005-list-and-proposed-subcommands.md) の `list` と同じ列挙）。ADRに限らず、READMEや仕様なども対象にする。
- 「コミット済みのADR」は、ADRのパス（[ADR 0002](0002-module-adr-directories.md) の `is_adr_path`）にあって `HEAD` に存在するファイルとする。

### `adr-guard links [--fix [--include-committed]]`

- `adr-guard links` は、対象の文書にあるリンクの無い参照を、`<パス>:<行>: ADR <番号> にリンクがありません` の形で1件ずつ標準エラーに表示する。
  - 1件でもあれば、最後に修正の方法（`adr-guard links --fix`、コミット済みのADRには `--include-committed`）を表示して終了コード1で終わる。無ければ何も表示せずに終了コード0で終わる。
- `adr-guard links --fix` は、コミット済みのADRを除く対象の文書について、リンクの無い参照をリンクに置きかえてファイルを書きかえる。
  - リンクは `[ADR <番号>](<文書のディレクトリから参照先への相対パス>)` とする。区切って続く番号は `[<番号>](<相対パス>)` とし、区切りの文字はそのまま残す（例：`[ADR 0005](0005-x.md)、[0006](0006-y.md)`）。
  - 書きかえたファイルごとに `<パス>: <件数>件の参照をリンクにしました` を標準エラーに表示する。
  - コミット済みのADRにリンクの無い参照が残っていれば、`<パス>:<行>: ADR <番号> にリンクがありません（コミット済みのADR。--include-committed で修正できます）` を表示し、終了コード1で終わる。残っていなければ終了コード0で終わる。
- `adr-guard links --fix --include-committed` は、コミット済みのADRも書きかえる。書きかえたADRをコミットするには、検査に `--allow-links` が必要になる（次節）。
- `--include-committed` は `--fix` と一緒にだけ使える。

### `--allow-links`（`pre-commit` と `check-range`）

- `adr-guard pre-commit --allow-links` と `adr-guard check-range --allow-links <base> <head>` では、コミット済みのADRの変更のうち、ADRの参照のリンクだけが異なる変更を許可する。
  - 変更の前後の内容で、ステータスの行の正規化（従来どおり）に加えて、テキストが `ADR <4桁の数字>` または `<4桁の数字>` のインラインのリンク（`[ADR 0001](...)`、`[0006](...)`）をテキストだけに置きかえてから比較し、一致すれば許可する。
  - リンクを付ける、外す、リンク先を変える変更が許可される。リンクのテキストを変える変更や、それ以外の本文の変更は従来どおり拒否する。
- `--allow-links` を付けない場合の挙動は変えない。
- `--allow-links` は [ADR 0008](0008-allow-intentional-adr-rewrites.md) のトレーラーと環境変数とは独立している。どちらでも許可されれば許可する。

### `adr-guard pre-commit` でのリンクの検査

- コミット済みのADRの検査（従来どおり）に加えて、ステージされた追加・変更の `.md` のファイルの、インデックスの内容を検査する。リンクの無い参照があれば、`pre-commit: <パス>:<行>: ADR <番号> にリンクがありません` を表示し、`adr-guard links --fix` で修正できることを案内して、終了コード1で終わる。
  - 参照先の解決には作業ツリーのADRのディレクトリを使う。
  - ステージされていない文書は検査しない。
  - `ADR_GUARD_ALLOW` はこの検査を許可しない（ADRの書きかえの許可とは別のため）。

### 引数

- オプションは、サブコマンドの後ろであればどの位置に置いてもよい（`check-range --allow-links <base> <head>` と `check-range <base> <head> --allow-links` は同じ）。
- 同じオプションを2回付けた場合、サブコマンドが受け付けないオプションを付けた場合、位置引数の数が合わない場合は、使い方の1行を標準エラーに表示して終了コード64で終わる。
- 使い方の1行を次に変える。

  ```
  usage: adr-guard <pre-commit [--allow-links]|claude-hook|check-range [--allow-links] <base> <head>|list [--status]|proposed [--status]|links [--fix [--include-committed]]|--version|--help>
  ```

### `--help`

AIがヘルプだけを読んで、どのサブコマンドを、どの場面で、どう呼べばよいかを判断できるようにする。
ヘルプは日本語で、次の節をこの順に含める。

- `adr-guard <バージョン>` の1行（[ADR 0003](0003-version-and-help-options.md) のとおり）
- 概要：コミット済みのADRを、ステータスの行を除いて変更できないようにするツールであること
- ADRとステータス：ADRのディレクトリ（`docs/adr/`、`docs/<モジュール>/adr/`）、ステータスの行（行頭の `ステータス:`）、ステータスの値の例（`提案`、`採択`、`採択→...`、`却下`、`破棄`）
- 規則：コミット済みのADRで許可される変更と拒否される変更、ADRの参照にリンクが要ること
- サブコマンド：サブコマンドごとに、書式、用途（どの場面で呼ぶか）、オプション、出力の形、終了コード
- 意図して書きかえる場合：`--allow-links`、`ADR_GUARD_ALLOW`、`ADR-Guard-Allow` のトレーラーの違いと使い分け（トレーラーは緊急用であること）
- 終了コードの一覧：0（成功）、1（違反、または実行の失敗）、2（`claude-hook` での拒否）、64（引数の誤り）
- 例：pre-commit hook（`exec adr-guard pre-commit --allow-links`）、CIでの `check-range`、レビュー待ちのADRを開く（`adr-guard proposed`）、リンクの修正（`adr-guard links --fix`）

### composite action（`action.yml`）

- 入力 `allow-links`（既定は `false`）を加え、`true` のときは `check-range` に `--allow-links` を付ける。
- `check-range` の後に、チェックアウトした作業ツリーで `adr-guard links` を実行する。
- 入力 `links`（既定は `true`）を加え、`false` のときは `links` を実行しない。既存の文書の移行が済むまで、使う側のリポジトリが検査を止められるようにする。

### このリポジトリ

- `.githooks/pre-commit` を `pre-commit --allow-links` にする。
- CIの `adr` ジョブで、`check-range --allow-links` とし、その後に `cargo run -- links` を実行する。
- `adr-guard links --fix --include-committed` で既存の文書を修正してコミットする（現時点では [ADR 0004](0004-release-version-options-as-patch.md) のタイトルの `ADR 0003` が対象になる）。トレーラーは使わない。

### ドキュメントとリリース

- `docs/specifications.md` と `README.md` に、`links`、`--allow-links`、pre-commit・actionでの検査を記載する。
- READMEに、既存のリポジトリで導入するときの移行の手順（hookとactionに `--allow-links` を付ける、`links --fix --include-committed` で修正してコミットする、移行が済むまでactionを `links: false` にする）を記載する。
- READMEの「意図してADRを書きかえる場合」に、トレーラーは緊急用であり、リンクの修正には `--allow-links` を使うことを記載する。
- pre-commit hookとCIの結果が変わるため、マイナーバージョンを上げて `v0.4.0` としてリリースする。

## 実装しないこと

- Claude Codeのhook（`claude-hook`）でのリンクの検査と、`--allow-links`。Claude Codeにリンクを付けさせる場合は、`adr-guard links --fix` をシェルから実行させる。
- `ADR0001`、`ADR-0001`、`adr 0001`、全角の空白など、`ADR 0001` 以外の書き方の検出。
- 参照先が見つからない参照（番号の誤りなど）のエラー。
- リンクの参照先が存在するかの検査（リンク切れの検出）。
- モジュールをまたぐ参照（`docs/server/` の文書から `docs/adr/` のADRを指す場合など）の自動の解決。参照先の規則で決まらない参照は、人がリンクを書く。
- 範囲内の各コミットの文書のリンクの検査。CIでは、チェックアウトした時点の作業ツリーだけを検査する。
- サブコマンドごとのヘルプ（`adr-guard links --help` など）と、英語のヘルプ。
- `--allow-links` を既定にすること。hookとactionで明示して有効にする。

## テスト設計

### 単体テスト

参照の検出と置きかえ：

- `ADR 0001` を検出し、`[ADR 0001](<パス>)` に置きかえる。
- `ADR 0005、0006` と `ADR 0005, 0006` を、`[ADR 0005](...)、[0006](...)` と `[ADR 0005](...), [0006](...)` に置きかえる。
- 1行に複数の参照があれば、すべて置きかえる。
- 次は検出しない：`[ADR 0001](x.md)`、`[参照：ADR 0001](x.md)`、`[ADR 0001][1]`、`` `ADR 0001` ``、``` `` `ADR 0001` `` ```、フェンス（` ``` ` と `~~~`）の中、`ADR0001`、`ADR-0001`、`adr 0001`、`ADR 001`、`ADR 00012`、`XADR 0001`。
- ADRのファイルの中で、自身の番号の参照は検出しない。

参照先：

- ディレクトリの解決：`README.md` → `docs/adr/`、`docs/specifications.md` → `docs/adr/`、`docs/adr/x.md` → `docs/adr/`、`docs/server/adr/x.md` と `docs/server/notes.md` → `docs/server/adr/`（番号があれば）、`docs/server/notes.md` で `docs/server/adr/` に番号が無ければ `docs/adr/`。
- 相対パス：`README.md` からは `docs/adr/0001-a.md`、`docs/specifications.md` からは `adr/0001-a.md`、`docs/adr/0002-b.md` からは `0001-a.md`、`docs/server/notes.md` からは `adr/0001-a.md`。

リンクだけの変更の判定：

- リンクを付ける、外す、リンク先を変える変更は、リンクだけの変更である。
- リンクのテキストを変える変更（`[ADR 0001](a.md)` → `[ADR 0002](a.md)`）と、本文を変える変更は、リンクだけの変更ではない。
- ステータスの行の変更とリンクの変更が同じ変更に含まれていても、リンクだけの変更（とステータスの変更）とみなす。

### 結合テスト

既存のテストは変えずにすべて通す。そのうえで、ADR（`docs/adr/0001-a.md`、`0002-b.md`、`docs/server/adr/0001-a.md`）と文書を置いた一時リポジトリで、次を確かめる。

`links`：

- リンクの無い参照を `<パス>:<行>` とともに報告して終了コード1、無ければ終了コード0。参照先が無い番号（`ADR 0099`）は報告しない。
- `--fix`：コミット済みのADR以外を書きかえ、コミット済みのADRに参照が残れば `--include-committed` を案内して終了コード1、残らなければ終了コード0。リンク済みの参照やコードの中は変わらない。
- `--fix --include-committed`（と `--include-committed --fix`）：コミット済みのADRも書きかえ、その後の `links` が終了コード0になる。
- `links x`、`links --include-committed`、`links --fix --fix` で終了コード64、gitのリポジトリの外で終了コード1。

`--allow-links`：

- `--fix --include-committed` で書きかえたコミット済みのADRを、`pre-commit` は拒否し、`pre-commit --allow-links` は許可する。
- 同じ書きかえのコミットを、`check-range` は拒否し、`check-range --allow-links`（オプションを前に置く場合と後ろに置く場合）は許可する。
- リンクのテキストや本文を変えた変更は、`--allow-links` を付けても拒否する。

`pre-commit` でのリンクの検査：

- リンクの無い参照を含む文書をステージすると失敗し、リンクを付けると成功する。ステージしていない文書の参照では失敗しない。`ADR_GUARD_ALLOW` を付けてもリンクの検査は失敗する。

`--help`：

- 出力に、すべてのサブコマンドとオプション（`--allow-links`、`--fix`、`--include-committed`、`--status`）、`ADR_GUARD_ALLOW`、`ADR-Guard-Allow`、終了コード（0、1、2、64）が含まれる。

### リリース

`v0.4.0` のリリース後、ダウンロードしたバイナリでこのリポジトリの `adr-guard links` が終了コード0で終わることと、`adr-guard --help` が上の節を含むことを確かめる。

## トレードオフ

- 参照先が見つからない参照をエラーにしないため、番号を誤った参照は検出できない。また、ほかのリポジトリのADRへの参照（`send-to-kindle の ADR 0001`）は、同じ番号のADRがこのリポジトリにもあると、このリポジトリのADRへのリンクとして報告・修正される。ほかのリポジトリのADRへの参照には、手でリンクを付けるか、インラインのコードにする。
- `--allow-links` を付けると、リンク先だけを書きかえる変更も通る。リンク先は本文の意味を変えないため許可する。リンクのテキストは本文の一部として扱い、変更を拒否する。
- `--fix` が既定でコミット済みのADRを書きかえないため、移行には `--include-committed` を明示する必要がある。コミット済みのADRを書きかえることを、使う人が意識して選ぶようにする。
- pre-commit hookは文書をまるごと検査するため、既存の文書にリンクの無い参照が残っていると、その文書を変更するたびに止まる。導入時に `links --fix --include-committed` で一度に移行する手順を示して補う。
- CIではチェックアウトした時点の作業ツリーを検査するため、`check-range` と違い、範囲の途中のコミットの文書は検査しない。リンクは最終的な状態にあればよく、途中の状態は問わない。
- actionの既定で `links` を実行するため、v0.4.0 に上げると、移行していないリポジトリのCIは失敗する。`links: false` で止められるようにして補う。
- Markdownの構文を完全には解析せず、フェンス、インラインのコード、リンクのテキストだけを除外する。HTMLのタグやコメントの中の参照も検出する。
- ヘルプを詳しくするため長くなる。人が読むには冗長だが、AIが1回の呼び出しで使い方を把握できることを優先する。
