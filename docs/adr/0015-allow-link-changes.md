# ADR 0015: `--allow-links` で、ADRの参照以外のリンクを付ける・外す・リンク先を変える変更も許可する

ステータス: 採択

## 文脈

`--allow-links` は、コミット済みのADRで、ADRの参照のリンクだけが異なる変更を許可する（[ADR 0009](0009-require-links-for-adr-references.md)）。
対象は、テキストが `ADR <4桁>` か `<4桁>` のインラインのリンク（`[ADR 0001](...)`、`[0006](...)`）に限られる。

一方、ADRには、ADRの参照以外のリンクも書く。

- ほかのリポジトリのADRや文書へのリンク（`[tett23/send-to-kindle](https://github.com/tett23/send-to-kindle)`、`[ADR 0009](https://github.com/...)` を含む文のリンクなど）
- 仕様書やREADMEへのリンク（`[仕様](../specifications.md)`）
- 参考文献のURL

これらのリンク先は、リポジトリの名前の変更、ファイルの移動、ブランチの名前の変更（`blob/master` から `blob/main` など）、外部のサイトのURLの変更で、ADRの内容と関係なく古くなる。
しかし、いまはリンク先を直すだけの変更も本文の変更として拒否され、直すには緊急用のトレーラー（[ADR 0008](0008-allow-intentional-adr-rewrites.md)）が要る。

リンク先はADRの内容（決定とその理由）ではなく、それを指す場所である。
同じく、ある語句にリンクを付けるか外すかも、読み手が見る文面を変えない。
リンクのテキストを変えずに、リンクを付ける・外す・リンク先を直す変更は、ADRの参照のリンクと同じく `--allow-links` で許可する。

## 実装すること

### 許可する変更

`--allow-links` を付けたとき、コミット済みのADRの変更前と変更後の内容に、次の処理を順に施してから比較する（ステータスの行の正規化は従来どおり `--allow-status` で行う）。

1. インラインのリンク `[テキスト](リンク先)` と参照形式のリンク `[テキスト][ラベル]` を、テキストだけに置きかえる。ADRの参照のリンク（従来どおり。[ADR 0009](0009-require-links-for-adr-references.md)）と、それ以外のリンクを区別しない。
2. 画像（直前が `!` のもの）は、インラインの `![代替テキスト](リンク先)` を `![代替テキスト]()` に、参照形式の `![代替テキスト][ラベル]` を `![代替テキスト][]` に置きかえる（リンク先だけを取り除く）。画像を加える・除く変更は、表示される内容を変えるため許可しない。
3. リンクの参照定義の行（行頭から3つまでの空白、`[ラベル]:`、リンク先、任意のタイトル。例：`[1]: https://example.com "例"`）を、行ごと取り除く。

その結果、次の変更が許可される。

| 変更前 | 変更後 | 許可 |
|---|---|---|
| `[仕様](../specifications.md)` | `[仕様](../../docs/specifications.md)` | する（リンク先の変更） |
| `[本家](https://github.com/a/b/blob/master/x.md)` | `[本家](https://github.com/a/b/blob/main/x.md)` | する |
| `![図](images/a.png)` | `![図](assets/a.png)` | する |
| `[1]: https://example.com/old` | `[1]: https://example.com/new "タイトル"` | する（参照定義のリンク先とタイトルの変更） |
| `[ADR 0001](0001-a.md)` | `ADR 0001` | する（従来どおり） |
| `[仕様](a.md)` | `仕様` | する（リンクを外す変更） |
| `仕様` | `[仕様](a.md)` | する（リンクを付ける変更） |
| `仕様` | `[仕様][1]` と、末尾に `[1]: a.md` の行を加える | する（参照形式のリンクを付ける変更） |
| `[仕様](a.md)` | `[仕様書](a.md)` | しない（テキストの変更） |
| `![図](a.png)` | `図` | しない（画像を除く変更） |
| `<https://example.com/old>` | `<https://example.com/new>` | しない（自動リンクは本文の一部とみなす） |
| `https://example.com/old` | `https://example.com/new` | しない（本文のURL） |
| `` `[仕様](a.md)` `` | `` `[仕様](b.md)` `` | しない（インラインのコードの中） |

- フェンスで囲んだコードブロックとインラインのコードの中は、リンクとみなさない（[ADR 0009](0009-require-links-for-adr-references.md) と同じ区別）。
- リンクのテキストの中のリンク（入れ子）は扱わない。外側のリンクをテキストだけに置きかえる。
- 参照定義の行を加える・除く変更は、行ごと取り除いてから比較するため許可される。参照定義の行の前後の空行を加える・除く変更は、本文の変更として拒否する。

### 適用する範囲

- `pre-commit --allow-links` と `check-range --allow-links`（actionの `allow-links: true`）で適用する。
- 記録（`docs/audit/` など。[ADR 0013](0013-protect-audit-and-benchmark-records.md)、[0014](0014-directory-name-variants.md)）には適用しない。記録には従来どおり例外を設けない。
- `claude-hook` は従来どおり `--allow-links` を受け付けない。

### `--help`、README、仕様

- `--help`、README、`docs/specifications.md` の `--allow-links` の説明を、「リンク（ADRの参照に限らない）を付ける・外す・リンク先を変える変更と、画像のリンク先を変える変更を許可する」に改める。

### リリース

- `--allow-links` を付けたときに許可される変更が広がるだけで、これまで通っていたコミットが拒否されることはないため、パッチバージョンを上げて `v0.8.2` としてリリースする（[ADR 0004](0004-release-version-options-as-patch.md) の判断）。
- 採択後、[ADR 0009](0009-require-links-for-adr-references.md) のステータスを `採択→--allow-links で許可する変更は[ADR 0015](0015-allow-link-changes.md)` にする。

## 実装しないこと

- 画像を加える・除く変更の許可。
- 自動リンク（`<https://...>`）と、本文に書いたURLの変更の許可。
- リンクのテキストの変更の許可。
- リンク先が実在するか、変更後のリンク先が変更前と同じ文書を指すかの検査。
- 別のオプション（`--allow-link-urls` など）を設けること。`--allow-links` の意味を「リンクに関する、内容を変えない変更」として広げる。
- 記録への適用。

## テスト設計

### 既存のテスト

既存のテストは変えずにすべて通す。[ADR 0009](0009-require-links-for-adr-references.md) のテストのうち、`--allow-links` を付けても拒否されることを確かめているもの（リンクのテキストの変更、本文の変更）は、この変更の後も拒否される。

### 単体テスト

- リンク先を取り除く正規化：上の表のすべての行について、`allowed_change` に `--allow-links`（`--allow-status` なし）を与えたときの許可・拒否を確かめる。
- フェンスの中とインラインのコードの中のリンクは正規化しない（`` `[a](b)` `` は変わらない）。
- 1行に複数のリンクがあり、その一部のリンク先だけを変える変更、一部だけを付ける・外す変更を許可する。
- 参照形式のリンク：`[a][1]` と `[a][]` をテキスト `a` に正規化する。
- 画像：`![a](b.png)` を `![a]()` に、`![a][1]` を `![a][]` に正規化し、`a` にはしない。
- 参照定義の行：`[1]: url`、`[1]: url "title"`、`   [label]: <url>` の行を取り除く。行頭の空白が4つ以上の行（コードとみなされる）と、フェンスの中の行は取り除かない。
- `--allow-links` が無ければ、リンク先の変更を拒否する。
- `--allow-status` と組み合わせて、ステータスの行とリンク先を同時に変える変更を許可する。

### 結合テスト

- コミット済みのADRの `[仕様](../specifications.md)` を `[仕様](../../specifications.md)` に変えた変更を、`pre-commit` は拒否し、`pre-commit --allow-links` は許可する。同じ変更のコミットを、`check-range --allow-links` は許可する。
- 同じADRの `仕様` に `[仕様](a.md)` とリンクを付けた変更を、`pre-commit --allow-links` は許可し、`--allow-links` が無ければ拒否する。
- 同じADRの `[仕様](a.md)` を `[仕様書](a.md)` に変えた変更を、`pre-commit --allow-links` は拒否する。
- コミット済みの記録（`docs/audit/a.md`）のリンク先の変更を、`pre-commit --allow-links` は拒否する。

### リリース

`v0.8.2` のリリース後、ダウンロードしたバイナリで、一時リポジトリのコミット済みのADRのリンク先の変更とリンクの追加を `pre-commit --allow-links` が許可し、テキストの変更を拒否することを確かめる。

## トレードオフ

- `--allow-links` で、リンク先を別の文書に差しかえることや、語句に新しくリンクを付けることもできる。リンクは読み手を別の文書に導くため、意味を補うことはありうる。しかし、リンクのテキスト（読み手が見る文面）は変えられないため、ADRの文面は保たれる。リンク先が適切かは、プルリクエストのレビューで確かめる。
- 自動リンクと本文のURLは対象にしない。リンクの構文として区別できるものに限り、規則を単純に保つ。古くなったURLを直したい場合は、リンクの形（`[テキスト](URL)`）で書いておく。
- 既存の `--allow-links` の意味を広げるため、`--allow-links` を付けているリポジトリでは、上げた後にリンク先の変更が通るようになる。許可が広がる方向の変更であり、CIが失敗するようになることはない。
- Markdownの構文を完全には解析しない（[ADR 0009](0009-require-links-for-adr-references.md) と同じ）。HTMLの `<a href="...">` のリンク先の変更は許可しない。
