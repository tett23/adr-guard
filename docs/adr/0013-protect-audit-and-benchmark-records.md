# ADR 0013: `docs/audit/` と `docs/benchmarks/` のコミット済みのファイルも変更できないようにする

ステータス: 採択

## 文脈

adr-guard は、コミット済みのADRを変更できないようにする（[ADR 0001](0001-standalone-adr-guard.md)、[0010](0010-allow-status-option.md)）。

ADRのほかにも、作成した時点の記録として残し、あとから書きかえてはならない文書がある。

- 監査の結果（`docs/audit/`）：ある時点のコードや設定を調べた結果。あとから書きかえると、その時点で何が分かっていたかが失われる。
- 性能の計測のスナップショットと、バージョンごとの性能のグラフ（`docs/benchmarks/`）：ある時点の計測値。書きかえると、比較の基準が失われる。

これらを使う側のリポジトリでは、コミット後は変更しない運用にしているが、検出する手段がない。
実際に、使う側のリポジトリ（dotfiles）では、コミット済みの `docs/audit/` のファイルに未コミットの変更が入っていた。

一方、監査の記録の誤記など、人間が判断したうえで書きかえたい場合もある。
その場合は、[ADR 0008](0008-allow-intentional-adr-rewrites.md) の緊急用の手段（トレーラーと環境変数）で許可する。

## 実装すること

### 保護する記録のパスの判定

リポジトリのルートからの相対パス（区切りは `/`）を `/` で分けた要素の並びについて、次のどちらかがあれば「記録」とする。

- 連続する要素 `docs`、`<種類>` の後ろに、1つ以上の要素がある（`<前>/docs/<種類>/<…>`）
- 連続する要素 `docs`、`<モジュール>`、`<種類>` の後ろに、1つ以上の要素がある（`<前>/docs/<モジュール>/<種類>/<…>`）。`<モジュール>` は空でない

`<種類>` は `audit` または `benchmarks` とする。`<前>` は0個以上の空でない要素で、ADRのパスの判定（[ADR 0002](0002-module-adr-directories.md)、[0011](0011-nested-adr-directories.md)）と同じ形にそろえる。

| パス | 記録か |
|---|---|
| `docs/audit/2026-10-07-best-practices.md` | はい |
| `docs/benchmarks/v0.1.0.json`、`docs/benchmarks/graphs/latency.svg` | はい |
| `docs/server/audit/2026-10-07.md` | はい |
| `packages/server/docs/benchmarks/v1.csv` | はい |
| `docs/audits/a.md`、`docs/benchmark/a.md` | いいえ（名前が違う） |
| `docs/a/b/audit/a.md` | いいえ（モジュールが2段） |
| `benchmarks/a.json`、`packages/server/audit/a.md` | いいえ（`docs` を挟まない） |

拡張子は問わない（`.md`、`.json`、`.csv`、画像など、すべて）。

### 規則

- コミット済みの記録の変更、削除、移動（リネーム）を違反とする。新しい記録の追加と、未コミットの記録の編集は自由にできる。
- ADRと違い、例外として許可する変更は無い。`--allow-status` と `--allow-links`（[ADR 0009](0009-require-links-for-adr-references.md)、[0010](0010-allow-status-option.md)）は記録には効かない。
- 違反のメッセージは次のとおりとする。
  - 変更：`コミット済みの記録（docs/audit/、docs/benchmarks/）は変更できません: <パス>`
  - 削除・移動：`コミット済みの記録（docs/audit/、docs/benchmarks/）は削除・移動できません: <パス>`
  - 違反があったときの案内は、ADRの案内（`仕様を変更する場合は、新しいADRを作成してください。`）に加えて、`記録を直す場合は、新しい記録を作成してください。` を表示する（記録の違反があったときだけ）。

### 検査する場所

ADRと同じ3か所で検査する。

- `pre-commit`：ステージされた変更のうち、記録の変更・削除・移動を違反とする。
- `check-range`：範囲内の各コミットで、記録の変更・削除・移動を違反とする。
- `claude-hook`：コミット済みの記録を変える Write・Edit・MultiEdit を、終了コード2で拒否する。`--allow-status` を付けても、記録の変更は拒否する。

### 意図して書きかえる場合

- [ADR 0008](0008-allow-intentional-adr-rewrites.md) の手段で許可する。
  - `check-range`：コミットメッセージのトレーラー `ADR-Guard-Allow: <理由>` があるコミットでは、記録の変更・削除・移動も違反としない。
  - `pre-commit`：環境変数 `ADR_GUARD_ALLOW` が空でなければ、記録の違反も許可する。
- トレーラーと環境変数の名前は、ADRに限らず保護しているファイル全体の許可として、そのまま使う。
- `claude-hook` には許可の手段が無い（従来どおり）。

### `links` との関係

- `links` は、従来どおり記録の `.md` も検査する（すべての `.md` が対象のため）。
- `links --fix` は、コミット済みの記録を、コミット済みのADRと同じく既定で書きかえない。`--include-committed` を付けたときだけ書きかえる。ただし、書きかえた記録のコミットには、`--allow-links` ではなくトレーラーと環境変数が要る。
  - `--include-committed` でコミット済みの記録を書きかえたときは、`<パス>: コミット済みの記録です。コミットには ADR-Guard-Allow のトレーラーが要ります` を表示する。

### `--help`、README、仕様

- `--help` の「規則」に記録の保護を加え、「意図してADRを書きかえる場合」を、記録にも及ぶことが分かる見出しと内容に変える。
- README と `docs/specifications.md` に、記録のパス、規則、許可の手段、`links --fix` の扱いを記載する。
- `src/main.rs` の先頭のコメントを更新する。

### リリース

- 保護の対象が広がり、pre-commit hook とCIの結果が変わるため、マイナーバージョンを上げてリリースする（[ADR 0012](0012-status-line-and-status-adt.md) を先にリリースするなら `v0.8.0`）。

## 実装しないこと

- `audit` と `benchmarks` 以外の記録のディレクトリ（`docs/reports/`、`docs/benchmark/` など）や、設定での追加。必要になったらADRで追加する。
- 記録に、`--allow-status` や `--allow-links` に当たる例外を設けること。
- 記録の形式（ファイル名の日付、`.md` の構成など）の検査。
- 記録の `list` や `proposed` に当たる一覧のサブコマンド。

## テスト設計

### 既存のテスト

既存のテストは変えずにすべて通す。

### 単体テスト

- 記録のパスの判定：上の表のすべてのパスを確かめる。ADRのパス（`docs/adr/0001-a.md`）は記録ではなく、記録のパスはADRではない。
- 違反のメッセージ：記録の変更・削除のメッセージと、ADRのメッセージが入れちがわない。

### 結合テスト

`docs/audit/2026-10-07.md` と `docs/benchmarks/v0.1.0.json` をコミットした一時リポジトリで、次を確かめる。

- `pre-commit`：記録の変更・削除・移動を拒否し、案内に `新しい記録を作成してください` が含まれる。新しい記録の追加は許可する。`--allow-status --allow-links` を付けても、記録の変更は拒否する。`ADR_GUARD_ALLOW` を付けると許可する。
- `check-range`：記録を変えたコミットを拒否し、`ADR-Guard-Allow` のトレーラーを付けたコミットは許可する。
- `claude-hook --allow-status`：コミット済みの記録の編集を終了コード2で拒否し、未コミットの記録の編集は許可する。
- `links --fix`：コミット済みの記録のリンクの無い参照を書きかえず、`--include-committed` で書きかえ、トレーラーが要ることを表示する。
- 記録とADRの違反が同じ変更にあれば、両方が報告される。

### リリース

リリース後、ダウンロードしたバイナリで、一時リポジトリの `docs/audit/` のコミット済みのファイルの変更を `pre-commit` が拒否することを確かめる。

## トレードオフ

- 記録には例外が無いため、誤記を直すだけでもトレーラーが要る。記録は作成した時点の内容を残すことに価値があり、直すなら新しい記録を作るのが原則のため、日常的な手段を設けない。
- `links` の検査は記録の `.md` にも及ぶため、リンクの無い参照を含む記録をコミットすると、あとからリンクを付けるにはトレーラーが要る。記録をコミットする前に `adr-guard links --fix` で直す運用で補う。
- 名前を `audit` と `benchmarks` に固定するため、`docs/audits/` や `docs/benchmark/` に置いている記録は保護されない。決め打ちの名前は、このツールを使うリポジトリの運用（`docs/audit/`、`docs/benchmarks/`）に合わせた。
- トレーラーと環境変数の名前（`ADR-Guard-Allow`、`ADR_GUARD_ALLOW`）は、記録の許可にも使うため、名前と範囲が一致しなくなる。名前を変えると既存の運用が変わるため、そのまま使う。
- 使う側のリポジトリに、コミット済みの記録への変更が未コミットのまま残っていると、v0.8.0 に上げた後はコミットできない。変更を取り消すか、トレーラーと環境変数で許可する。
