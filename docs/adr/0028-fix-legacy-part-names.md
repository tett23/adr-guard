# ADR 0028: 旧形式の部分名から修飾子と区切りの記号を除き、決められない部分名を移行しない

Status: proposed

## 文脈

[ADR 0022](0022-status-transitions.md) の移行スクリプト（`scripts/migrate-adr-status`）は、旧形式の `採択→…` の行を、部分名と修正先の列に分けて新形式に書く。
部分名の作り方は、[ADR 0026](0026-read-more-legacy-references.md) が「前の参照の後から参照の前までの文字列から、前後の空白、先頭の読点、末尾の `は` を除いたもの」と定めた。

v0.13.0 の移行スクリプトを tett23 のリポジトリで実行すると、旧形式の行の意味と合わない部分名を作る。
部分名は自由な文字列なので、pre-commit、`check-range`、`check-status` のどれもこの誤りを見つけない。
そのまま `--write` で書くと、誤った部分名がコミットされる。

この ADR は、部分名の作り方を直す。
規則で正しく決められない行は、移行スクリプトが移行できないADRとして報告し、人か AI が新形式で書く。

## 調査した事項

v0.13.0（`0096636`）でビルドした移行スクリプトの `--dry-run` を、tett23 のリポジトリ（dotfiles を含む）の既定のブランチの最新で実行し、出力の部分名を調べた。

### 修飾子が部分名に残る

golem では、部分名433個のうち108個が、`診断の出力順は golem-syntax` のように、末尾に ` は ` と1語を残した。
tett23 では、部分名7個のうち4個が、`Golem のページの言語は tett23.github.io` のように残した。
ほかのリポジトリには、この形はなかった。

残る語は、`golem-syntax ADR 0003` や `[tett23.github.io ADR 0001](…)` のように、`ADR NNNN` の直前の語（[ADR 0019](0019-module-qualified-adr-references.md) の修飾子）である。
`src/status.rs` の `legacy_refs` は、参照の始まりを `ADR` の位置とする。
そのため、修飾子は前の部分名の側に入る。
v0.12.0 の `changes_ja` も、部分名を `ADR` の位置で切っていた（`git show v0.12.0:src/status.rs` の `part(&text[from..sequence.start])`）。
この不具合は v0.12.0 からある。

### 区切りの記号が部分名に残る

golem では、部分名3個が、`。先頭の連続 BOM は Golem` のように `。` で始まった。
前の変更と句点で区切った行である。

novel-crawler では、`docs/adr/0009` と `docs/adr/0029` の部分名が、末尾に `は→` を残した。
元の行は `採択→判定を scripts/adr-guard.ts に置き、Bash の後にも検査する部分は→[ADR 0035](0035-follow-global-adr-rules.md)` の形である。
`part` は末尾の `は` を除くが、その後ろの `→` を除かない。

### 部分名の途中に参照がある

golem には、修正先でない参照を部分名の途中に書いた行がある。
次の行の `[golem-layout ADR 0016](…)` は、部分名「…正規形の比べ方、`golem-layout ADR 0016` の回帰の述語、L7 の 3 行の段落」の一部である。

`ステータス: 採択→（L4 の読み方）は [golem-layout ADR 0028](…)、正規形と縦組みのテストの段、上限の変数、正規形の比べ方、[golem-layout ADR 0016](…) の回帰の述語、L7 の 3 行の段落は [ADR 0211](…)、…`

移行スクリプトは、0016 を修正先とする変更と、部分名「の回帰の述語、L7 の 3 行の段落」で修正先 0211 の変更の2つに分けた。

golem `docs/adr/0044` の `…根拠の決定は、docs/adr/0021 ではなく [docs/adr/0004](…) にある、…` も、参照の後に部分名の続き（` にある`）がある。

### 括弧の途中で切れる

golem `docs/golem-font/adr/0002` の行は次のとおりである。

`ステータス: 採択→…ToUnicode を作る処理は golem-driver に移した（[golem-driver ADR 0030](…)）、`FontFile3` の `Subtype` は [golem-pdf ADR 0011](…)`

移行スクリプトは、部分名を `ToUnicode を作る処理は golem-driver に移した（golem-driver` と `）、`FontFile3` の `Subtype` は golem-pdf` にした。
括弧が二つの部分名に分かれている。

### 件数の見積もり

スクラッチのスクリプトで、旧形式の `採択→…` の行のうち、次の行を数えた。
参照は、リンク先のファイル名が `<4桁の数字>-` で始まるリンクと、リンクの外の `ADR NNNN` とした。

- 最後でない参照の後ろから次の参照の前までが、空白を除いて区切り（`、`、`,`、`。`、閉じ括弧で始まる文字列、`と`、`および`）でない行：golem の238行のうち7行。
- 参照で区切った部分名のうち、開き括弧と閉じ括弧の数が合わないものを持つ行：golem の238行のうち2行。

ほかのリポジトリには、どちらの行もなかった。
この数は見積もりであり、実装の後に `--dry-run` で数え直す。

## 用語

- 変更、部分名、参照、区切り：[ADR 0026](0026-read-more-legacy-references.md) の用語と同じ。
- 修飾子：[ADR 0019](0019-module-qualified-adr-references.md) の修飾子。`ADR` の直前に半角の空白1つをはさんで置かれた、`A-Z`、`a-z`、`0-9`、`.`、`_`、`/`、`-` の最も長い続きで、英数字で始まる語。
- 決められない部分名：この ADR の規則で、旧形式の行の意味と合う部分名を作れないもの。

## 実装すること

### 修飾子を参照に含める

旧形式の参照の範囲（部分名を切る位置）を、次のとおりにする。

- 参照がリンクの中にあれば、参照はリンクの文字の始まりから始まる。
- 参照がリンクの外にあり、`ADR` の直前に修飾子があれば、参照は修飾子の始まりから始まる。

この変更は、部分名を切る位置だけを変える。
修正先の解決（[ADR 0019](0019-module-qualified-adr-references.md)、[ADR 0023](0023-trace-amendments.md)）で修飾子をどう使うかは変えない。

### 区切りの記号を除く

部分名から、前後の空白に加えて、次を除く。

- 先頭の `、`、`,`、`。`。
- 末尾の `→`。続けて、いまと同じく末尾の `は` を除く。

### 決められない部分名を移行しない

移行スクリプトは、旧形式の `採択→…` と `置換…` の行に、次のどちらかがあれば、その行を移行できないADRとして報告する。
報告は `<パス>:<行>: 部分名を決められません: <理由>` とする。

- 最後でない参照の後ろから次の参照の前までが、区切りでなく、`、`、`,`、`。`、閉じ括弧のどれでも始まらない。理由は `参照の後ろに部分名の続きがあります`。
- 参照で区切った部分名のどれかで、開き括弧（`（`、`(`）と閉じ括弧（`）`、`)`）の数が合わない。理由は `括弧が部分名をまたぎます`。

この判定は移行スクリプトだけで行う。
pre-commit と `check-range` が旧形式の行を読むとき（[ADR 0022](0022-status-transitions.md) の旧形式と新形式の比較）は、いまと同じく変更に分ける。
そのため、決められない部分名を持つ行を人や AI が新形式に書きかえても、比較は Superseded から Superseded への遷移（UpdateRevisions）として通る。

### 文書

`docs/specifications.md` の旧形式の部分名の作り方と、移行スクリプトの説明を直す。

## 実装しないこと

- 決められない部分名を、規則を足して自動で決めること。括弧や途中の参照の書き方はリポジトリごとに違い、規則で決めると誤った部分名を黙って書く。
- 移行済みの新形式の行の部分名を直すこと。新形式の部分名は、書いた人が決めたものとして扱う。
- 修飾子の判定に、モジュールのADRのディレクトリがあるかを使うこと（[ADR 0019](0019-module-qualified-adr-references.md) の名前の修飾子の規則）。部分名を切る位置には、語の形だけを使う。

## 不変条件

1. 旧形式の行から得た部分名は、修飾子で終わらない。
2. 旧形式の行から得た部分名は、`、`、`,`、`。` で始まらず、`→` で終わらない。
3. 移行スクリプトが新形式に書く行の部分名は、どれも開き括弧と閉じ括弧の数が等しい。
4. 最後でない参照の後ろに部分名の続きがある行は、移行スクリプトが移行できないADRとして報告し、書かない。
5. 修飾子も区切りの記号も途中の参照も持たない旧形式の行の変更の列は、この ADR の前と変わらない。

| 旧形式の行（`ステータス: ` の後ろ） | 期待 |
|---|---|
| `採択→a は golem-x ADR 0002` | 部分名 a |
| `採択→a は [golem-x ADR 0002](…)` | 部分名 a |
| `採択→a は [x.example ADR 0002](https://…)` | 部分名 a |
| `採択→a は [ADR 0002](…)。b は [ADR 0003](…)` | 部分名 a と b |
| `採択→a は→[ADR 0002](…)` | 部分名 a |
| `採択→a、[ADR 0002](…) の述語、b は [ADR 0003](…)` | 移行できない（参照の後ろに部分名の続きがあります） |
| `採択→a は x に移した（[ADR 0002](…)）、b は [ADR 0003](…)` | 移行できない（括弧が部分名をまたぎます） |
| `採択→（a の読み方）は [ADR 0002](…)` | 部分名 `（a の読み方）`（括弧の数が等しい） |
| `採択→a は [ADR 0002](…) で消した` | 部分名 a、注記「で消した」（[ADR 0026](0026-read-more-legacy-references.md) のまま） |
| `採択→a は [ADR 0002](…)、b は [ADR 0003](…)` | 部分名 a と b（いまと同じ） |

## テスト設計

テストの名前には、`part_inv` に続けて不変条件の番号を入れる。

- `part_inv1_qualifier`：上の表の修飾子の行（リンクの外、リンクの中、URL のリンク）の部分名を確かめる。
- `part_inv2_delimiters`：句点で区切った行と、`は→` の行の部分名を確かめる。
- `part_inv3_brackets` と `part_inv4_ambiguous`：上の表の移行できない2行を移行スクリプトの `--dry-run` と `--write` に通し、報告の文と、終了コード1と、どのファイルも書きかわらないことを確かめる。括弧の数が等しい行は移ることも確かめる。
- `part_inv5_unchanged`：`src/status.rs`、`src/revisions.rs`、`tests/trace.rs`、`tests/legacy.rs`、`tests/migrate_status.rs` の既存の入力が、同じ変更の列に解決されることを確かめる。既存のテストは変えずに通す。
- pre-commit：一時リポジトリで、移行できない2行の旧形式をコミットし、手で書いた新形式の行へのコミットが pre-commit と `check-range` を通ることを確かめる。

### 実機での確認

実装の後、tett23 のリポジトリ（dotfiles を含む）で `--dry-run` を実行し、次を確かめる。

- golem と tett23 の部分名に、` は <修飾子>` で終わるものがない。
- golem の部分名に、`。` で始まるものがない。novel-crawler の部分名に、`→` で終わるものがない。
- 移行できないADRとして新たに報告される行が、上の見積もりの行（golem の `docs/adr/0044`、`docs/golem-font/adr/0002` など）であり、件数を数える。

## トレードオフ

- 修飾子を語の形だけで決めるので、`ADR NNNN` の直前の英数字の語は、修飾子でなくても部分名から外れる。たとえば `see ADR 0002` の `see` は部分名に入らない。調べたリポジトリの旧形式の `採択→…` の行で、修飾子でない英語の語が `ADR` の直前に来る行は数えていない（未確認）。日本語の行では、`ADR` の直前は空白か日本語の文字か修飾子であることが多いため、この影響を受け入れる。
- 決められない部分名を持つ行は、移行スクリプトでは移らない。golem では、見積もりで最大9行が人か AI の手に回る。誤った部分名を黙って書くより、手で書くほうを選ぶ。
- 参照の後ろに区切りの語や記号でなく注記と次の変更が続く行（`a は [ADR 0002](…) で消した、b は [ADR 0003](…)`）も、移行できないと報告する。最後の参照の後ろの注記は [ADR 0026](0026-read-more-legacy-references.md) のとおり移すが、途中の注記と次の部分名の境目は規則で決めない。
