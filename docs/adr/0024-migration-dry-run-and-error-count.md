# ADR 0024: 移行スクリプトに --dry-run を設け、失敗を最後まで数える

Status: proposed

## 文脈

[ADR 0022](0022-status-transitions.md) は、旧形式のステータス行を新形式に移す一度だけ使うスクリプト `scripts/migrate-adr-status` を定めた。
このスクリプトは対象リポジトリのルートで実行する。
引数なしで変更予定の差分を表示し、`--write` で作業ツリーに適用する。
変換できないADRを見つけたときは、該当パスと理由を示して終了コード1で終わる。

しかし、いまのスクリプトは、変換できない最初のADRで止まる。
そのため、一つのリポジトリにいくつ変換できないADRがあるかが分からない。
移行を始める前に、直す手間を見積もれない。
また、書き込むかどうかが引数の有無で決まるので、書き込まない実行であることがコマンドの上で読み取れない。

本人から次の2点を頼まれた。

- 移行スクリプトに dry run を設ける。
- 一つのリポジトリで1件でも変換できないADRがあれば、エラーとする。ただし、エラーの件数を知りたいので、書き込みをしないだけで、件数は最後まで数える。

## 調査した事項

`main`（`100c345`）の `scripts/migrate-adr-status` は、`cargo run --example migrate_adr_status` を呼ぶだけのシェルスクリプトである。
変換の本体は `examples/migrate_adr_status.rs` にある。

- `run` は、引数なしを差分の表示、`--write` だけを書き込みとし、それ以外を `使い方: migrate-adr-status [--write]` で終了コード1とする。
- `plan` は、ADRごとに変換案を作る。変換できないADRがあると、`?` でその場で `Err` を返す。そのため、後に続くADRは調べない。
- `write_rewrite` は、変換案を作ったときと内容が変わっていれば、そのADRで止まる。

一時リポジトリで確かめた。
`docs/adr/0001-a.md`（`ステータス: 謎`）、`docs/adr/0002-b.md`（`ステータス: 採択`）、`docs/adr/0003-c.md`（`ステータス: 不明な値`）を置いて実行した。
引数なしでも `--write` でも、表示は `docs/adr/0001-a.md:3: 注記または未知のステータスを保全して変換できません: 謎` の1行だけで、終了コードは1だった。
`0003-c.md` は報告されなかった。
`0002-b.md` は書きかわらなかった。

リリースのアーカイブには、`adr-guard` の実行ファイルと `LICENSE` と `README.md` だけを入れる（`.github/workflows/release.yml` の77行目）。
`scripts/` と `examples/` は入らない。

## 実装すること

### 用語

この ADR では、ADRごとの結果を次の3つに分ける。

- 移行できる：旧形式のステータス行を、新形式に変換できる。
- 移行済み：ステータス行がすでに新形式であり、変えない。
- 移行できない：変換できない。理由は [ADR 0022](0022-status-transitions.md) が定めるもの（注記の消失、未知の値、参照先の欠落や曖昧さ）と、ステータス行が1件でないこと、UTF-8 で読めないことである。

### 引数

- `--dry-run`：作業ツリーを変えずに、移行できるADRの差分を標準出力に表示する。差分の形は、いまの引数なしの表示と同じである。移行できないADRがあっても、移行できるADRの差分を表示する。
- `--write`：移行できるADRを作業ツリーに書き込む。
- 引数なし、両方の指定、それ以外の引数は、`使い方: migrate-adr-status --dry-run|--write` を標準エラーに表示して終了コード1で終わる。作業ツリーは変えない。

### 失敗の数え方

- どちらのモードでも、対象のADRをすべて調べる。移行できないADRを見つけても、残りのADRを調べ続ける。`--write` は、すべてを調べ終えてから書き込むかどうかを決める。
- 移行できないADRは、パスの順（いまと同じく、`git ls-files` で列挙したパスを並べかえた順）に、いまと同じ形（`<パス>:<行>: <理由>` か `<パス>: <理由>`）で標準エラーに1行ずつ表示する。
- 最後に、標準エラーに `移行できる: <N>件、移行済み: <K>件、移行できない: <M>件` の1行を表示する。
- 移行できないADRが1件以上あれば、終了コード1で終わる。`--write` でも、移行できるADRを含めて1件も書き込まない。
- 移行できないADRが0件なら、終了コード0で終わる。`--write` は、移行できるADRをすべて書き込む。

### ADRに結びつかない誤り

リポジトリのルートで実行していない、`git` が失敗したなど、ADRに結びつかない誤りは、いまと同じくその場で表示して終了コード1で終わる。
この場合は件数の行を表示しない。
書き込みの途中で内容が変わったADRを見つけた場合も、いまと同じくそのADRで止まる。

### 文書

README と `docs/specifications.md` の移行の手順を、`--dry-run` で確かめてから `--write` で適用する形に直す。

## 実装しないこと

- 複数のリポジトリをまとめて移行すること。スクリプトは、いまと同じく実行したリポジトリだけを扱う。
- 移行できないADRがあるときに、移行できるADRだけを書き込むこと。
- 件数を標準出力に出すこと。標準出力は差分だけとし、パイプで差分を読む使い方を変えない。
- 変換の規則そのものの変更。

## 不変条件

ADRの集合を、移行できる N 件、移行済み K 件、移行できない M 件に分ける。

1. 移行できない ADR が1件以上あれば、どちらのモードでも終了コードは1で、どのファイルのバイト列も変わらない。
2. 標準エラーに表示する移行できないADRの行数は M に等しく、件数の行は N、K、M を正しく示す。
3. `--dry-run` は、どのファイルのバイト列も変えない。
4. M が0のとき、`--write` の後の作業ツリーは、`--dry-run` が表示した差分を当てたものに等しい。
5. 引数なし、両方の指定、未知の引数は終了コード1で、どのファイルのバイト列も変えない。

| 移行できる N | 移行済み K | 移行できない M | `--dry-run` | `--write` |
|---|---|---|---|---|
| 0 | 0 | 0 | 終了コード0、差分なし | 終了コード0、変更なし |
| 0 | 1 | 0 | 終了コード0、差分なし | 終了コード0、変更なし |
| 1 | 0 | 0 | 終了コード0、差分1件 | 終了コード0、1件を書き込む |
| 1 | 0 | 1 | 終了コード1、差分1件、失敗1行 | 終了コード1、変更なし、失敗1行 |
| 1 | 0 | 2 | 終了コード1、失敗2行 | 終了コード1、変更なし、失敗2行 |
| 0 | 0 | 2 | 終了コード1、失敗2行 | 終了コード1、変更なし、失敗2行 |

## テスト設計

`tests/migrate_status.rs` に、次のテストを足す。
テストの名前には、`dry_run_inv` に続けて不変条件の番号を入れる。

- `dry_run_inv1_failures_block_all_writes`：移行できる1件と移行できない2件を置き、`--write` が終了コード1で終わり、すべてのファイルのバイト列が変わらないことを確かめる。
- `dry_run_inv2_counts_every_failure`：上の入力に移行済みの1件を足し、`--dry-run` と `--write` の両方が2件の失敗を2行で表示し、件数の行が `移行できる: 1件、移行済み: 1件、移行できない: 2件` になることを確かめる。失敗のADRを並びの先頭と末尾に置き、先頭で止まらないことを確かめる。
- `dry_run_inv3_never_writes`：上の表の各行の入力で、`--dry-run` の前後のバイト列が等しいことを確かめる。
- `dry_run_inv4_write_matches_preview`：M が0の入力で、`--dry-run` の差分と、`--write` の前後の差分が一致することを確かめる。
- `dry_run_inv5_usage`：引数なし、`--dry-run --write`、`--foo` が終了コード1で、バイト列を変えないことを確かめる。

既存のテストのうち、引数なしで差分を表示するものは `--dry-run` に直す。
それ以外の既存のテストは変えずに通す。

## トレードオフ

- 引数なしの実行を、差分の表示から使い方の誤りに変える。書き込むかどうかをいつもコマンドの上に明示するためである。いまの使い方（引数なしで差分を見る）は通らなくなるが、このスクリプトは一度だけ使うものであり、リリースのアーカイブにも入らないため、影響はソースから実行する利用に限られる。
- `--dry-run` と `--write` は同じ検査を通るので、`--dry-run` が終了コード0で終わった直後の `--write` は、作業ツリーが変わらない限り成功する。
- 移行できないADRがあると、移行できるADRも書き込まない。一部だけを移行した中間の状態をリポジトリに残さず、件数を見て全体を直してから一度に移行するためである。
