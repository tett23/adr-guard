# ADR 0005: ADRを一覧する `list` と `proposed` サブコマンド

ステータス: 採択→proposed の出力はADR 0006、list の出力はADR 0007

## 文脈

ADRは、作成した時点ではステータスを `提案` としてコミットせずに置き、人間のレビューで採択されてからコミットする。
レビュー待ちのADRがいくつあるか、どれがまだ採択されていないかを確かめるには、現状では各ADRのステータスの行を目で見るしかない。
モノレポで `docs/<モジュール>/adr/` にADRが分かれている場合（[ADR 0002](0002-module-adr-directories.md)）は、ADRがどこにあるかも見落としやすい。

ADRのパスを一覧する `list` と、ステータスが `提案` のADRをステータスとともに一覧する `proposed` のサブコマンドを加える。

## 実装すること

### `adr-guard list`

- 作業ツリーにあるすべてのADRのパスを、1行に1つずつ標準出力に出力し、終了コード0で終わる。ADRが無ければ何も出力せず、終了コード0で終わる。
- ステータスの行が無いADRも含める。

### `adr-guard proposed`

- 作業ツリーにあるADRのうち、ステータスが `提案` のものを、1行に1つずつ `<パス><タブ><ステータス>` の形で標準出力に出力し、終了コード0で終わる。該当するADRが無ければ何も出力せず、終了コード0で終わる。
  - `<ステータス>` は、ステータスの行の `ステータス:` より後ろの、前後の空白を除いた値（例：`提案`、`提案（レビュー中）`）とする。
  - 例：`docs/adr/0005-list-and-proposed-subcommands.md	提案`
- `adr-guard proposed --no-status` では、ステータスを出力せず、パスだけを1行に1つずつ出力する。`xargs` などにパイプで渡すために使う。
  - 対象のADRと並び順は `--no-status` を付けない場合と同じ。
  - オプションは `--no-status` だけを受け付ける。`proposed` の後ろに置く。

### 共通

- パスはリポジトリのルートからの相対パス（区切りは `/`）とし、パスの昇順に並べる。どのディレクトリで実行しても同じ出力になる。

### 対象のファイル

- `git ls-files --cached --others --exclude-standard -z` で、追跡されているファイルと、追跡されていないが無視もされていないファイルを列挙する。コミットせずに置いている提案中のADRも対象になる。
- そのうち、`is_adr_path`（[ADR 0002](0002-module-adr-directories.md)）に一致し、拡張子が `.md` のファイルをADRとする。
- 内容は作業ツリーから読む。追跡されているが作業ツリーで削除されているファイルは対象外とする。

### ステータスの判定

- 行頭が `ステータス:` で始まる最初の行を、ステータスの行とする（`pre-commit` などと同じ `ステータス:`）。
- ステータスの値が `提案` で始まれば、ステータスが提案のADRとする。
- ステータスの行が無いADRは、`proposed` の対象外とする。

### 引数の誤りとヘルプ

- `list` に引数が付いた場合や、`proposed` に `--no-status` 以外の引数が付いた場合（`--no-status` を2回付けた場合を含む）は、ほかの誤った引数と同じく使い方の1行を標準エラーに表示し、終了コード64で終わる。
- 使い方の1行を `usage: adr-guard <pre-commit|claude-hook|check-range <base> <head>|list|proposed [--no-status]|--version|--help>` に変え、ヘルプに `adr-guard list`（ADRを一覧する）と `adr-guard proposed [--no-status]`（ステータスが提案のADRを一覧する。`--no-status` ではパスだけを出力する）の説明を加える。
- gitのリポジトリの外で実行した場合など、ファイルを列挙できなければ、標準エラーにメッセージを表示して終了コード1で終わる。

### ドキュメントとリリース

- `docs/specifications.md` と `README.md` に `list` と `proposed` を記載する。
- 既存のサブコマンドの挙動を変えないため、[ADR 0004](0004-release-version-options-as-patch.md) にならってパッチバージョンを上げ、`v0.2.2` としてリリースする。

## 実装しないこと

- `提案` 以外のステータス（`却下`、`破棄` など）での絞り込み。
- `list` でのステータスの出力と、`list` の `--no-status`。`list` はもとからパスだけを出力する。
- `adr-guard --no-status proposed` のように、`--no-status` をサブコマンドの前に置く書き方。
- 提案のADRがあるときに失敗する終了コード（CIで提案のADRを検出する用途）。必要になったら別のADRで追加する。
- ステータスの行の全角のコロン（`ステータス：`）への対応。ほかのサブコマンドと同じく半角の `ステータス:` だけを扱う。
- コミット（`HEAD` など）の時点のADRを対象にすること。作業ツリーだけを見る。
- 他のサブコマンドの挙動の変更。

## テスト設計

### 単体テスト

ステータスを取り出す関数について、次を確かめる。

- `ステータス: 提案` の値は `提案`、`ステータス:提案` の値は `提案`、`ステータス: 提案（レビュー中） ` の値は `提案（レビュー中）` である。
- `ステータス: 採択`、`ステータス: 採択→ADRのディレクトリはADR 0002`、`ステータス: 却下`、`ステータス: 破棄` は提案ではない。
- ステータスの行が無い、`ステータス：提案`（全角のコロン）、行の途中にある `ステータス: 提案` は、ステータスが無いとみなす。
- ステータスの行が複数あるときは最初の行の値を使う。

### 結合テスト

既存のテストは変えずにすべて通す。そのうえで、次のファイルを置いた一時リポジトリで実行する。

- コミット済み：`docs/adr/0001-a.md`（採択）、`docs/adr/0002-b.md`（提案）、`docs/adr/0003-c.md`（採択→0004）、`docs/adr/0004-d.md`（却下）、`docs/adr/0005-e.md`（破棄）、`docs/adr/0006-f.md`（ステータスの行なし）、`docs/server/adr/0001-a.md`（提案（レビュー中））
- 未追跡：`docs/adr/0007-g.md`（提案）
- `.gitignore` で無視：`docs/adr/0008-h.md`（提案）
- ADRではない：`docs/notes.md`（提案）、`docs/a/b/adr/0001-a.md`（提案）、`docs/adr/0009-i.txt`（提案）
- コミット済みで作業ツリーから削除：`docs/adr/0010-j.md`（提案）

確かめること：

- `list`：標準出力が `docs/adr/0001-a.md` から `docs/adr/0007-g.md` までの7件と `docs/server/adr/0001-a.md` の8行で、この順に並び、終了コードが0である。
- `proposed`：標準出力が `docs/adr/0002-b.md	提案`、`docs/adr/0007-g.md	提案`、`docs/server/adr/0001-a.md	提案（レビュー中）` の3行で、この順に並び、終了コードが0である。
- `proposed --no-status`：標準出力が `docs/adr/0002-b.md`、`docs/adr/0007-g.md`、`docs/server/adr/0001-a.md` の3行で、この順に並び、終了コードが0である。
- サブディレクトリ（`docs/`）で実行しても、いずれも同じ出力になる。
- ADRが無いリポジトリでは、どちらも標準出力が空で終了コードが0である。
- gitのリポジトリの外では、どちらも終了コードが1である。
- `list x`、`list --no-status`、`proposed x`、`proposed --no-status x`、`proposed --no-status --no-status` では終了コードが64である。
- `--help` の出力に `list`、`proposed`、`--no-status` が含まれる。

### リリース

`v0.2.2` のリリース後、ダウンロードしたバイナリでこのリポジトリの `adr-guard list` と `adr-guard proposed` を実行し、`list` がADRのパスをすべて出力すること、`proposed` と `proposed --no-status` が提案のADRが無い場合に何も出力しないことを確かめる。

## トレードオフ

- 作業ツリーを見るため、未コミットの提案のADRを一覧できる一方、手元の状態によって出力が変わる。レビュー待ちを確かめるという用途では、手元の状態を見るのが適切と判断した。
- `proposed` の既定の出力は、人が読むためにステータスを付けたタブ区切りとし、パイプで渡す場合は `--no-status` でパスだけにする。`cut -f1` でも取り出せるが、オプションがあれば区切りを意識せずに使える。パスにタブを含むファイルはタブ区切りの出力が崩れるが、ADRのファイル名は連番とkebab-caseで付けるため、許容する。
- 出力は改行区切りで、`-z` などのNUL区切りには対応しない。パスに改行を含むADRは想定しない。
- `提案` で始まるかで判定するため、`提案` の後ろに補足を書いたステータスも提案として扱える。一方、`提案` で始まる別の意味のステータスを作った場合はそれも含まれる。
- `.md` 以外のファイルをADRとして扱わないため、ADRのディレクトリに置いた画像などは一覧されない。保護（`pre-commit` など）の対象は従来どおり `.md` 以外も含む。
