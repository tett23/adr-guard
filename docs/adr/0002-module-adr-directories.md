# ADR 0002: モノレポのモジュールごとのADR（`docs/<モジュール>/adr/`）も保護する

ステータス: 採択

## 文脈

adr-guard は、`docs/adr/` 以下のファイルだけをADRとして保護する（[ADR 0001](0001-standalone-adr-guard.md)）。
モノレポでは、ADRをモジュールごとに分けて `docs/<モジュール>/adr/`（例：`docs/server/adr/0001-xxx.md`）に置くことがある。
現状ではこれらのADRは対象外で、コミット済みでも本文を書きかえられる。

[ADR 0001](0001-standalone-adr-guard.md) は、ADRのディレクトリを設定ファイルやオプションで変えることを「実装しないこと」とし、必要になったらADRで追加するとしている。
ここでは設定は導入せず、ADRのディレクトリの判定に `docs/<モジュール>/adr/` を加える。
使う側のリポジトリは、hookやCIの設定を変えずに、adr-guard を更新するだけでモジュールごとのADRも保護できる。

## 実装すること

### ADRのパスの判定

リポジトリのルートからの相対パス（区切りは `/`）が、次のどちらかで始まるファイルをADRとする。

- `docs/adr/`（従来どおり）
- `docs/<モジュール>/adr/`。`<モジュール>` は空でない1つのパス要素（`/` を含まない）とする。

`adr/` より下の深さは問わない（従来の `docs/adr/` と同じ）。

| パス | ADRか |
|---|---|
| `docs/adr/0001-a.md` | はい（従来どおり） |
| `docs/server/adr/0001-a.md` | はい |
| `docs/server/adr/images/a.png` | はい |
| `docs/a/b/adr/0001-a.md` | いいえ（モジュールが2段） |
| `docs/server/adrs/0001-a.md` | いいえ |
| `docs/server/adr`（ファイル） | いいえ |
| `packages/server/docs/adr/0001-a.md` | いいえ（リポジトリ直下の `docs/` ではない） |

この判定を1つの関数（`is_adr_path`）にまとめ、3つのサブコマンドすべてで使う。

### サブコマンドの変更

- `pre-commit` と `check-range`：`git diff` にパスの指定（`-- docs/adr/`）を渡すのをやめ、全体の差分（`--name-status --no-renames -z`）から `is_adr_path` に一致するパスだけを検査する。
  - gitのpathspecの `*` は `/` をまたいで一致するため、`docs/*/adr/` を渡すと `docs/a/b/adr/` まで含まれる。判定をRust側の1か所に寄せ、`claude-hook` と食い違わないようにする。
- `claude-hook`：`docs/adr/` で始まるかの判定を `is_adr_path` に置きかえる。
- 判定以外の挙動（ステータスの行の判定 `ステータス:`、許可・拒否の規則、メッセージ、終了コード）は変えない。

### ドキュメントとリリース

- `docs/specifications.md` と `README.md` の対象のディレクトリの記述を更新する。READMEに、モノレポでは `docs/<モジュール>/adr/` も対象になることを記載する。
- 保護の対象が広がり、これまで通っていたコミットが拒否されうるため、マイナーバージョンを上げて `v0.2.0` としてリリースする。
- 採択後、[ADR 0001](0001-standalone-adr-guard.md) のステータスを `採択→ADRのディレクトリはADR 0002` に変更する。

## 実装しないこと

- ADRのディレクトリを設定ファイルやオプションで指定する機能。[ADR 0001](0001-standalone-adr-guard.md) に引き続き、必要になったらADRで追加する。
- `docs/a/b/adr/` のような2段以上のモジュール、`packages/<モジュール>/docs/adr/` のような `docs/` 以外の場所に置かれたADR。
- `docs/adr/` から `docs/<モジュール>/adr/` へのADRの移動（モノレポへの移行など）を許可すること。従来どおり、コミット済みのADRの移動は削除として拒否する。
- モジュールごとのADRの連番やファイル名の検査。

## テスト設計

### 単体テスト

`is_adr_path` について、上の表のすべてのパスに加え、次を確かめる。

- `docs/adr.md`、`docs/server/adr.md`、`src/docs/server/adr/a.md` はADRではない。
- `docs/adr/adr/a.md`（モジュール名が `adr`）はADRである。
- `docs/server/other/a.md` などADR以外の `docs/` 以下のファイルはADRではない。

### 結合テスト

既存のテストは変えずにすべて通す。そのうえで `docs/server/adr/` に置いたADRについて、次を追加する。

- `pre-commit`：ステータスの行だけの変更を許可し、本文の変更・削除・リネームを拒否する。新規追加を許可する。
- `pre-commit`：`docs/adr/` から `docs/server/adr/` への移動を拒否する。
- `pre-commit`：`docs/a/b/adr/` と `docs/server/notes/` のファイルの変更は検査しない。
- `claude-hook`：本文の変更を終了コード2で拒否し、ステータスの行だけの変更を許可する。
- `check-range`：範囲内で `docs/server/adr/` のADRの本文を変えたコミットがあれば失敗する。
- `docs/adr/` と `docs/server/adr/` の両方に違反がある場合、両方のパスが報告される。

### リリース

`v0.2.0` のリリース後、`tett23/adr-guard@v0.2.0` のcomposite actionを使う側のリポジトリで、ADRの検査が成功することを確かめる。

## トレードオフ

- 設定なしで `docs/<モジュール>/adr/` を対象にするため、ADRのつもりでない `docs/<何か>/adr/` もコミット後は変更できなくなる。`adr` という名前のディレクトリをADR以外に使うことはまれと判断し、設定を持たない単純さを優先する。
- 判定のために `git diff` を全体の差分で取るため、ADR以外の変更が多いコミットでは出力が増える。名前と状態だけの出力であり、問題になる量ではない。
- 既存のリポジトリをモノレポに移行してADRを `docs/<モジュール>/adr/` に移す場合、移動は拒否される。移行する場合は新しい場所に新しいADRを作成するか、`--no-verify` でコミットしたうえでCIの失敗を個別に判断する必要がある。移動の許可は、ADRを書きかえずに経緯を消せる抜け道になるため、今回は入れない。
- 1段のモジュールに限るため、`docs/<グループ>/<モジュール>/adr/` のような構成には対応しない。必要になったら判定を広げるADRを作成する。
